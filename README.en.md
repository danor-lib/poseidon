# @danor-lib/poseidon
![Version](https://img.shields.io/github/package-json/v/danor-lib/poseidon?style=flat-square)
[![License](https://img.shields.io/github/license/danor-lib/poseidon?style=flat-square)](https://opensource.org/license/mit)

A type-grouped data file management library for Node.js.

`Poseidon` consolidates multiple type-classified data files in the same directory into a single read-only large Object, replacing traditional function-based configuration/data retrieval and significantly reducing code volume and cognitive load. All loaded data is deeply frozen (read-only), and path-marked fields are automatically resolved to absolute paths.

> **Note**: Using `config` as the filename prefix in the documentation is merely a convention. In fact, `Poseidon` is fully decoupled; via the `prefix` option it can work with any type of data files (e.g., `state`, `data`, `setting`, etc.).

## Design Philosophy

Traditional configuration management usually requires accessing different classified data files through retrieval functions. The design goals of `Poseidon` are:

- **Construct once, access everywhere** – Map all classified data files under a directory into properties of a large Object via a Proxy.
- **Lazy loading** – No file is read during construction; files are loaded and cached only when first accessed.
- **Immutable data** – All loaded data is deeply frozen by default, preventing accidental modifications.
- **Extensible prefix** – `config` is just the default prefix; you can use it to manage `state`, `data`, or any other type-classified data files.

## Basic Example

````javascript
import { Poseidon } from '@danor-lib/poseidon';

// --- Create a Poseidon instance ---
const P = new Poseidon({ dirn: './config' });

// --- Direct access to classified data files ---
// config.apple.json → P.apple (supports any JSON type)
console.log(P.apple);  // { color: 'red', price: 5 }

// config.boy.json → P.boy
console.log(P.boy);    // { name: 'Tom', age: 12 }

// --- Fields of the default classification config.json are expanded to the top level ---
// If config.json = { cat: 'lihua' }, you can access directly:
console.log(P.cat);    // 'lihua'

// --- Use `$` to access management methods ---
console.log(P.$.selectExistTypes());

// --- Modify and save data ---
P.$.edit('apple', (data) => {
  data.price = 6;
  return data;
});

// --- Missing files return undefined (no error thrown by default) ---
console.log(P.unknown);  // undefined
````

## File Structure

````
config/
├── config.json               ← default classification (type = `_`), must be an Object
├── config.apple.json         ← normal classification `apple`, can be any JSON type
├── config.boy.json           ← normal classification `boy`
├── .config.secret.json       ← hidden file (Linux style, starting with `.`), higher priority than normal files
└── config.apple.backup1.json ← backup file (`selectExistTypes()` will list it under backups)
````

- Filename format: `{prefix}.{type}.{ext}`, where `prefix` defaults to `config`, `type` is the classification name, and `ext` is the extension.
- The default classification file is named `{prefix}.{ext}` (without the type segment), and internally uses `_` to represent it.
- Supported extensions are controlled by the `exts` option, defaulting to `['.json']`.

## Core Concepts

### Type & File Mapping

| Filename             | Type    | Access    | Description                                                                               |
| :------------------- | :------ | :-------- | :---------------------------------------------------------------------------------------- |
| `config.json`        | `_`     | `P.cat`   | Default classification, must be an Object; its fields are expanded to the Proxy top level |
| `config.apple.json`  | `apple` | `P.apple` | Normal classification, supports any JSON type (Object / Array / string / number …)        |
| `.config.apple.json` | `apple` | `P.apple` | Hidden file, higher priority than `config.apple.json`                                     |

### Reserved Types

The following type names are reserved by Poseidon internally and **cannot be used as data classifications**:

| Reserved Type | Purpose                             | Description                                                                                                                                                         |
| :------------ | :---------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `$`           | Access management methods           | `P.$` returns the Poseidon instance itself, used to call `read` / `load` / `save` / `edit` methods                                                                  |
| `_`           | Default classification identifier   | Used in management methods like `P.$.read('_')` to denote the default classification. `P._` can return `config.json` data but is **not recommended** for direct use |
| `constructor` | JavaScript prototype chain property | Due to JS class design, accessing `P.constructor` does not trigger the Proxy getter, so it cannot be used for data classification                                   |

> This means files like `config.$.json`, `config._.json`, `config.constructor.json` will **not be loaded**.

### Default Classification and Field Expansion

The default classification (`_`, i.e., `config.json`) must be an Object. Its top-level fields are **expanded** onto the Proxy, allowing direct access like normal properties:

````jsonc
// config.json
{ "cat": "lihua", "host": "localhost" }
````

````javascript
const P = new Poseidon({ dirn: './config' });
console.log(P.cat);   // 'lihua'
console.log(P.host);  // 'localhost'
````

Non-default classifications are accessed as a whole by their type name, without expansion.

### Type Conflict and `preferDefault`

When a field name in the default classification `config.json` **collides** with another classification filename:

````
config/
├── config.json       ← content: { "apple": "red" }
└── config.apple.json ← content: { "color": "green" }
````

Then accessing `P.apple` – should it return `"red"` from `config.json`, or `{ color: "green" }` from `config.apple.json`?

This is determined by the `preferDefault` option:

| `preferDefault`  | Behaviour                                                                    |
| :--------------- | :--------------------------------------------------------------------------- |
| `true` (default) | Prefer the value from the default classification. `P.apple` → `"red"`        |
| `false`          | Prefer the independent classification file. `P.apple` → `{ color: "green" }` |

### PoseidonBox Wrapper Class

The `Poseidon` imported from `@danor-lib/poseidon` is actually the `PoseidonBox` class. It is a **wrapper class** whose constructor directly returns a Poseidon instance (the Proxy), but its prototype chain points to `PoseidonBox`.

This design serves two purposes:

1. **Clean IntelliSense** – `PoseidonBox` has only `$` and `constructor` properties, so the editor will not mix management methods (like `read`, `save`) into the data property hints.
2. **Facilitates TypeScript type extensions** – Users can declare types for specific classifications via `declare module`:

````typescript
declare module '@danor-lib/poseidon' {
  interface Poseidon {
    readonly 'apple': { color: string; price: number; };
    readonly 'boy': { name: string; age: number; };
  }
}

export { }; // Marks the file as a module
````

This way, accessing `P.apple` in the editor provides full type hints.

> If you need to use the core class directly (e.g., for subclassing), you can import `Poseidon_`:
> ````javascript
> import { Poseidon_ } from '@danor-lib/poseidon';
> ````

## Constructor

### `new Poseidon(options?)`

Creates a Poseidon instance, returning a Proxy object.

- **Parameters** `options` `{Object}` – Optional. All properties are optional.

| Option          | Type                     | Default          | Description                                                                                       |
| :-------------- | :----------------------- | :--------------- | :------------------------------------------------------------------------------------------------ |
| `prefix`        | `string`                 | `'config'`       | Data file prefix. Set to `'state'` to read `state.xxx.json` files.                                |
| `dirn`          | `string`                 | `process.cwd()`  | Directory where data files reside.                                                                |
| `preloads`      | `string \| string[]`     | `[]`             | Types to preload. A string can be comma-separated, e.g., `'_,apple'`.                             |
| `exts`          | `string[]`               | `['.json']`      | Supported extension list; earlier ones have higher priority.                                      |
| `parser`        | `(buffer, self) => data` | `JSON.parse`     | Custom parsing function.                                                                          |
| `packer`        | `(data, self) => string` | `JSON.stringify` | Custom serialisation function.                                                                    |
| `preferDefault` | `boolean`                | `true`           | Whether to prefer the default classification value when a conflict with a standalone file occurs. |
| `willFreeze`    | `boolean`                | `true`           | Whether to deeply freeze data after loading.                                                      |
| `absolutize`    | `Object`                 | see below        | Path absolutisation configuration.                                                                |
| `howAssign`     | `'throw' \| 'ignore'`    | `'throw'`        | Behaviour when assigning to the Proxy.                                                            |

`absolutize` sub-options:

| Sub-option  | Type      | Default | Description                                                         |
| :---------- | :-------- | :------ | :------------------------------------------------------------------ |
| `enable`    | `boolean` | `true`  | Whether to enable path absolutisation.                              |
| `prefix`    | `string`  | `'_'`   | Key prefix that triggers absolutisation.                            |
| `overwrite` | `boolean` | `true`  | Whether to overwrite existing properties with the same name.        |
| `path`      | `string`  | `''`    | Intermediate path between the data directory and the relative path. |

````javascript
// Using default options
const P = new Poseidon();

// Custom directory and prefix
const P = new Poseidon({ dirn: './data', prefix: 'state' });

// Preload multiple types
const P = new Poseidon({ preloads: '_,apple,boy' });
// Equivalent to
const P = new Poseidon({ preloads: ['_', 'apple', 'boy'] });

// Custom parser (e.g., JSONC support)
import JSONC from 'comment-json';

const P = new Poseidon({
  exts: ['.jsonc', '.json'],
  parser: (buf) => JSONC.parse(buf.toString()),
  packer: (data) => JSONC.stringify(data, null, '\t'),
});

// Disable freezing and path absolutisation
const P = new Poseidon({ willFreeze: false, absolutize: { enable: false } });
````

### `$.read(type, willParse?)`

Reads the raw content of a data file, without freezing or path transformation.

- **Parameters**:
  - `type` `{string}` – Type name.
  - `willParse` `{boolean}` – Default `true`. If `true`, returns parsed data; if `false`, returns the raw Buffer.
- **Returns**: Parsed data or Buffer.

````javascript
const data = P.$.read('apple');          // returns parsed data
const buffer = P.$.read('apple', false); // returns raw Buffer
````

### `$.load(type, willThrow?)`

Loads a data file. Data is deeply frozen (if enabled), and path-marked fields are converted to absolute paths (if enabled). Can be reloaded to overwrite the cache.

- **Parameters**:
  - `type` `{string}` – Type name.
  - `willThrow` `{boolean}` – Default `false`. If `true`, throws an error when the file does not exist; if `false`, returns `undefined`.
- **Returns**: Frozen data, or `undefined`.

````javascript
P.$.load('apple');            // loads and caches
P.$.load('apple');            // reloads, overwriting old cache
P.$.load('unknown', true);    // throws if file does not exist
````

### `$.save(type, data, options?)`

Writes data to a file. Supports automatic backup before writing.

- **Parameters**:
  - `type` `{string}` – Type name.
  - `data` `{any}` – Data to save.
  - `options` `{Object}` – Optional.
    - `willBackup` `{boolean}` – Default `false`. If `true`, backs up the existing file before writing.
    - `dirnBackup` `{string}` – Backup/write directory, defaults to the instance's `dirnData`.
    - `padBackup` `{number}` – Minimum length for backup ID, zero-padded if needed, default `1`.
    - `prefix` `{string}` – File prefix, defaults to the instance's `prefixFile`.
    - `ext` `{string}` – Extension, defaults to the instance's `extensions[0]`.
- **Returns**: The `Poseidon` instance, for chaining.

````javascript
// Normal save
P.$.save('apple', { color: 'red', price: 6 });

// Save with backup
P.$.save('apple', newData, { willBackup: true });
// Backup files: config.apple.backup1.json → config.apple.backup2.json …

// Save backup to a different directory
P.$.save('apple', data, { willBackup: true, dirnBackup: './backup' });
````

### `$.edit(type, handle)`

A convenience method to modify, save, and reload data. Supports synchronous and asynchronous callbacks.

- **Parameters**:
  - `type` `{string}` – Type name.
  - `handle` `{(data, dataRaw, type, self) => newData}` – Modification callback. Receives the current parsed data, raw Buffer, type name, and the Poseidon instance itself; returns the modified data. If the callback returns a Promise, it is automatically awaited.
- **Returns**: The `Poseidon` instance (asynchronously returns a `Promise<Poseidon>`).

````javascript
// Synchronous modification
P.$.edit('apple', (data) => {
  data.price = 10;
  return data;
});

// Asynchronous modification
await P.$.edit('apple', async (data, _raw, _type, self) => {
  const remote = await fetchRemoteData();
  return { ...data, ...remote };
});
````

### `$.selectExistTypes()`

Scans the data directory and lists all types along with their files and backup information.

- **Returns**: `Record<string, { files: FileInfo[], backups: BackupInfo[] }>` – Keyed by type name; each type contains `files` (list of normal files) and `backups` (list of backup files).

````javascript
const info = P.$.selectExistTypes();
````
Example structure of `info`:
````json
{
  _: {
    files: [{ hidden: false, type: '_', backup: false, ext: '.json', file: 'config.json' }],
    backups: []
  },
  apple: {
    files: [
      { hidden: false, type: 'apple', backup: false, ext: '.json', file: 'config.apple.json' },
      { hidden: true,  type: 'apple', backup: false, ext: '.json', file: '.config.apple.json' }
    ],
    backups: [
      { hidden: false, type: 'apple', backup: 1, ext: '.json', file: 'config.apple.backup1.json' }
    ]
  }
}
````
````javascript
// Get all available type names
const types = Object.keys(P.$.selectExistTypes());
console.log(types); // ['_', 'apple', 'boy']
````

## Advanced Features

### 1. Proxy Access

`new Poseidon(...)` returns a Proxy object. The access behaviour is as follows:

1. **Reserved properties first** – `$` returns the Poseidon instance; `constructor` returns the class constructor.
2. **Type match** – If the key is already cached, the corresponding type data is returned directly.
3. **Default classification expansion** – If the default classification (`_`) is an Object, attempt to look up the key in its fields (`preferDefault` controls priority).
4. **Lazy loading** – If none of the above match, automatically call `load(key)` safely (if the file is missing, returns `undefined`).
5. **Assignment forbidden** – The Proxy setter, when `howAssign='throw'` (default), throws a `forbidden-set` error.

````javascript
const P = new Poseidon({ dirn: './config' });

// config.json = { host: 'localhost' }
P.host;   // Matches rule 3: expanded from default classification

// config.apple.json exists
P.apple;  // Matches rule 4: auto lazy load

// Reserved properties
P.$;           // Matches rule 1: Poseidon instance
P.constructor; // Matches rule 1: PoseidonBox constructor

// Assignment behaviour
P.host = 'new';  // Throws forbidden-set error (default)
````

### 2. Path Absolutisation

All keys in the data object that start with `_` (customisable via `absolutize.prefix`) have their string values automatically resolved to absolute paths (relative to `dirnData` + `absolutize.path`):

````jsonc
// config.apple.json
{
  "_pathIcon": "./icons/apple.png",
  "_pathData": "../data/apple.dat",
  "nested": {
    "_cacheDir": "./cache"
  },
  "normalKey": "remains unchanged"
}
````

After loading:

````javascript
const P = new Poseidon({ dirn: '/app/config' });

console.log(P.apple.pathIcon);          // '/app/config/icons/apple.png'
console.log(P.apple._pathIcon);         // './icons/apple.png' (original value preserved)
console.log(P.apple.pathData);          // '/app/data/apple.dat'
console.log(P.apple.nested.cacheDir);   // '/app/config/cache'
console.log(P.apple.normalKey);         // 'remains unchanged'
````

Rules:
- Only string values are processed; nested Objects are recursed.
- The absolutised key loses the `_` prefix. If the target key already exists and `absolutize.overwrite` is `false`, the transformation is skipped.
- The original prefixed key remains unchanged.

### 3. Deep Freeze

All data loaded via `load()` is recursively deep-frozen (`Object.freeze`) by default. Any modification attempts will throw errors in strict mode. To modify data, you must use `edit()` or `save()`.

Deep freezing can be disabled via the `willFreeze: false` option.

### 4. Backup Mechanism

The `save()` method supports the `willBackup` option. When enabled, the existing file is copied as a backup before being overwritten.

Backup file naming: `{prefix}.{type}.backup{n}.{ext}`, where `{n}` is an auto-incrementing sequence:

````
config/
├── config.apple.json            ← current data
├── config.apple.backup1.json    ← 1st backup
├── config.apple.backup2.json    ← 2nd backup
└── config.apple.backup3.json    ← 3rd backup
````

`selectExistTypes()` will include backup files in the `backups` array, distinguishing them from normal files.

### 5. Hidden Files

Poseidon supports Linux-style hidden files (filenames starting with `.`). When both `.config.apple.json` and `config.apple.json` exist, the hidden file has **higher priority** (it is tried first in `read()`).

### 6. Custom Parser and Extensions

Through the `exts`, `parser`, and `packer` options, any file format can be supported:

````javascript
// JSONC example
import JSONC from 'comment-json';

const P = new Poseidon({
  exts: ['.jsonc', '.json'],
  parser: (buf) => JSONC.parse(buf.toString()),
  packer: (data) => JSONC.stringify(data, null, '\t'),
});

// YAML example (requires `yaml` package)
import { parse as parseYAML, stringify as stringifyYAML } from 'yaml';

const P = new Poseidon({
  exts: ['.yaml', '.yml', '.json'],
  parser: (buf) => parseYAML(buf.toString()),
  packer: (data) => stringifyYAML(data),
});
````

### 7. Custom Prefix

By changing the `prefix` option, you can make Poseidon manage different types of data files:

````javascript
// Manage state files: state.apple.json, state.boy.json, state.json …
const state = new Poseidon({ dirn: './data', prefix: 'state' });

// Manage data files: data.apple.json, data.boy.json, data.json …
const store = new Poseidon({ dirn: './data', prefix: 'data' });
````

### 8. Lazy Loading and Preloading

By default, **no file is read** when constructing a Poseidon instance. Data is loaded and cached only when first accessed via the Proxy.

If you need to load certain types immediately upon construction, use the `preloads` option:

````javascript
// Load config.json and config.apple.json immediately on construction
const P = new Poseidon({ preloads: '_,apple' });
````
